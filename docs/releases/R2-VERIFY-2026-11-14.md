## Operational differences and remaining validation

The external `G:\FILOW\tmp\orchestrator\release.ps1` was left untouched. Its SHA256 is
`CC64D519421A1D425F934067987F9596584037DC506D4FFA78A3E6889D419077`.
The repository counterpart uses `preflight`, `draft`, `publish`; it does not bump versions,
commit, fast-forward another checkout, push, tag, or edit source-release notes. It replaces
the asset count and partial regex hash loop with the tested verifier, requires the owner's
stored gh login, creates a feed draft, verifies fresh draft downloads and smoke evidence,
checks the tag again, sets Latest last, and compares the feed manifest readback. Errors and
timeouts stop the script. It deliberately refuses to overwrite old staging directories.

CI no longer receives or uses RELEASES_TOKEN. All actions remain SHA-pinned. Its prebuild
check rejects an already released tag. Manual `smoke_only` dispatch skips that check and
all rebuilding, including when dispatched at a tag ref. The separate smoke job uses only
the default token and a clean Windows runner. Since that token cannot read another repo's
private draft, it tests the source installer; publication binds the result to the actual
draft download by SHA512. Startup requires a hydrated welcome/loaded page, a live native
window and five seconds without exit or a startup failure.

Before using this for a release, a human must validate the manual CI smoke job and the
PowerShell 7 draft/publish flow. Neither was executed here, as GitHub writes and workflow
runs were forbidden. Review the empty account-origin allowlist before enabling production
accounts. D6 still owns certificate identity and publisherName. The verifier reads embedded
metadata only from the Windows NSIS x64 installer; other platform assets are named and
hash-checked. The first paid release still needs the manual upgrade check in the checklist.
Latest readback failure is detected after publication, so follow recall immediately; the
two repositories cannot provide an atomic tag-check/publish transaction. Recall does not
undo already installed or cached updates.
