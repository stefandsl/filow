# Reference projects: what Filow takes from each, and under which licence

Studied 2026-11-02 for the real-time point-recognition plan. "Pattern" means the idea was re-implemented
in Filow's own code after reading; no code was copied. Licences as found in each repository on that day.

| Repository | Licence | What it does | Taken into Filow | Not taken, and why |
|---|---|---|---|---|
| Priler/jarvis (Rust; the author's two videos are summarised in VIDEO-NOTES.md) | CC BY-NC-SA 4.0 (non-commercial, share-alike: code cannot be copied into Filow) | Voice assistant: intent classification with cached sentence embeddings, model registry, audio stages, ring buffer | Pattern: embedding classifier with vectors prepared ahead and cached under a content hash, cosine at query time → `packages/core/src/gate.ts` (several candidates per window instead of one winner, explicit "no match"); model registry idea is already the Ollama inventory + router | Rust audio pipeline (Filow's STT runs in a Node worker), ring buffer (sherpa streams; nothing to drop) |
| zms618/VoiceCue (Electron, React, TS) | **UNLICENSED** (`package.json`, no LICENSE file: all rights reserved) | Word-by-word prompter that follows the voice; Python child process with faster-whisper / sherpa-onnx; token Levenshtein matcher with 0.7/0.8/0.82 thresholds, two-tier commit (partials speculative, finals committed), 4-gram jump recovery, 3 s audio backlog cap | Patterns worth adopting later: partials speculative vs finals committed (provisional vs confirmed mark, plan step 5), two-final confirmation for far jumps, backlog cap with a discontinuity reset, `\p{L}` tokenisation so Cyrillic survives | Everything word-level (Filow checks whether a point was addressed, not where the cursor is); the Python/PyInstaller runtime; very young (one visible commit, 2026-09), Chinese-first |
| bogdanripa/my-prompter (iOS) | All rights reserved (README) | Script mode with points ticked while speaking; keyword matching | Interaction reference only (ticked points while speaking is what Filow does) | Code; keyword matching does not cover paraphrase |
| mdonmez/moves-cli (Python) | GPL-3.0, archived 2026-08-05 | Local STT, phonetic + semantic comparison with prepared content, slide advance | Idea: preparation separated from execution (Filow's point vectors are prepared when the script loads) | GPL and archived: not a dependency |
| guidalleprane/prompter (Python) | GPL-3.0 | faster-whisper + RapidFuzz fuzzy follow of a script, LAN display | Warning taken: its normaliser keeps only a–z and digits, so Cyrillic is lost; Filow's gate works on raw text through the multilingual model, and any future fuzzy step must use Unicode-aware tokens | GPL; verbatim following only |
| larsbaunwall/promptme-ai (JS) | Apache-2.0 | Audio/STT worker and local script matching in JavaScript | Closest stack; permissive. Nothing needed yet: Filow already has the worker split | English-only phonetics |
| SallyZhou9527/prompter (Tauri/Rust) | MIT | sherpa-onnx or Vosk native integration, document import | Confirms sherpa-onnx as the STT choice | A Rust rewrite is not shown to be faster (plan: native code only for a measured bottleneck) |
| AeCeCi/STT-Presentation-Review | not checked | Compares presentation material with speech, Korean, cloud services | Evaluation idea: compare prepared material against what was said after the fact (a "review" export could reuse Filow's live notes) | Not local, not multilingual |

Rule kept from the plan: a licence that forbids copying still allows learning the shape of a solution;
anything taken is rewritten and tested in Filow's own terms (`gate.test.ts`, `engine.test.ts`).
