# Safe preparation evidence

Local branch `feat-safe-prep`, based on `771ddf1`. No merge, push, tag, release, origin configuration or billing switch change.

## Pilot updates

The package boolean `updates=false` closes the updater at its loader, check and startup scheduling boundaries. Since the updater is never loaded, neither download listeners nor automatic installation on quit are registered. Menu and IPC installation use the same guarded install function. A disabled menu label exists in EN/IT/RU/RO/JA; normal absent/true metadata keeps existing behavior.

Tests execute main.js with fake Electron/updater effects, including manual and automatic checks, stale downloaded state, normal installation and five translated disabled menu labels. Two mutations (ignore metadata; remove loader guard) are caught. Native menu popup rendering and packaged install/return-to-public transitions were not exercised: no visible menu was opened.

## Closed checkout

`FILOW_LIVE_BILLING` is passed from configuration as an explicit boolean. Default/off checkout returns 503 `billing_not_open`, without invoking Stripe. `/v1/me` carries the checkout state; desktop IPC preserves a closure received after page load as data rather than a custom Error property. The account page replaces Subscribe with plain EN/IT/RU/RO/JA text. Existing paid subscribers retain Manage subscription; webhook and price logic is unchanged.

Service tests cover default/off with all checkout-related Stripe methods spied, plus the existing live-on checkout test. Desktop tests cover the typed IPC return without opening a URL. Two mutations (remove the guard; default to enabled) are caught. Hidden account-page rendering uses fake account data, not a deployed service or real Stripe. Live billing, SMTP and a deployed sign-in flow are not verified.

## Opt-in release origin

`--require-account-origin` takes a comma-separated list of exact HTTPS origins and applies to fixture, verify and audit. Missing or non-allowlisted installer metadata fails only under that explicit policy; default behavior is preserved. Seven new offline CLI tests cover absent, approved, wrong, malformed and missing-argument cases. Two mutations (remove required-origin check; remove allowlist check) are caught. No origin was set and no release command contacted GitHub. The PowerShell release wrapper's production metadata/policy wiring remains an owner-gated follow-up.

## Five caption tracks

The generator reads one translated source with shared 0/6/12/18-second boundaries. Tests compare generated files, all three nonempty cues per language, language switching and unknown-language English fallback. Line endings are normalized in the asset test for Windows checkouts. The first-run welcome selects the matching native text track when the UI language changes, preserving a user's caption-off choice on unrelated renders. `/tour` has no video and was left unchanged. All four new translations need a native-language check.

Hidden QA used the actual bundled welcome page and actual bundled React account page with fake account/preference bridges. Both windows stayed hidden; microphone permission was denied. Profile, screenshots and results are under `G:/FILOW/tmp/safe-prep`; only HTTP 4981 and debugging 9581 were used (4982-4985 unused). `FILOW_QA_NO_GLOBAL_INPUT=1` and `FILOW_QA_HEADLESS=1` were set. Ten language/theme combinations passed for account text/button replacement and caption loading/selection/active text, silent playback and page overflow; twenty screenshots were captured. Representative EN/IT account and RU/JA caption screenshots were visually inspected in both themes. This was a renderer fixture, not a full packaged-app or installed-profile test. No native popup, microphone, real screen input, model, provider, SMTP or Stripe connection was used. The harness denied network requests outside its local HTTP server, used a 120-second deadline and exited; its parent had a 140-second deadline.

A caption-selection mutation is also caught. The reproducible seven-case runner is `tools/release/test/safe-prep-mutations.mjs`; output is `tmp/safe-prep/mutations.json`. It restores each source in `finally` and requires failed test assertions, not merely a crashed runner.

## Validation and limits

`npm ci` succeeded with caches/temp under this worktree on G:. The initial sandbox attempt failed registry access; the authorized retry succeeded. npm reported existing dependency engine/deprecation warnings, including unpdf requiring Node 24 while this project uses Node 22. The lockfile was not changed.

The initial full run had resource-contention timeouts and missing generated bundles/Electron access. `npm run build:welcome -w apps/desktop` generated the ignored bundles; the final suite uses four workers and the QA isolation flags. Final checks and exact counts are recorded in HANDOFF. All seven mutations were caught and restored. Early renderer fixture attempts failed because its standalone JSX/Next environment shim was incomplete; corrected fixture checks passed without changing product behavior to suit the harness.

Not verified: real installer update suppression and manual pilot-to-public transitions; deployed account/Stripe behavior; owner-approved production origin/release wrapper integration; native translation review and full F1 clean-VM acceptance. None of the paid provider, assist, allowance, price or webhook work was attempted. AGENTS.md was modified by tooling and is deliberately excluded from all commits.
